# AGENTS.md

SafeGrid — academic disaster-preparedness platform. Two independent halves; **no root manifest, no workspace tooling**. Install, run, and test each side separately.

## Repo shape

- `backend/` — Python 3.11+, FastAPI, stdlib SQLite. Entry point `backend/app/main.py` (run from `backend/`).
- `frontend/` — Vite 5 + `vite-plugin-pwa`, MapLibre GL JS. Entry `frontend/src/main.js`.
- Backend is the **single source of truth for risk calculations**; the frontend only renders GeoJSON.
- Most modules are scaffolded stubs with TODOs. `docs/API.md` is a **DRAFT** — `/health`, `/api/data`, and `/api/hazards` are registered in `backend/app/main.py`; `/api/risk-zones` is documented but still a stub. Don't assume docs describe working code.

## Commands

Backend (always from `backend/` — pyproject `testpaths = ["tests"]` lives there):

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt   # both files needed
uvicorn app.main:app --reload        # :8000, docs at /docs
pytest                               # 15 tests
pytest tests/test_db.py -k rainfall  # single focused run
```

Frontend (from `frontend/`):

```bash
npm ci          # lockfile is committed; do not casually regenerate it
npm run dev     # :5173, proxies /api and /health to localhost:8000
npm run build   # this is the CI gate
```

- **No linter, formatter, or typechecker is configured anywhere** — don't invent a lint step; `pytest` + `npm run build` are the only checks.
- CI (`.github/workflows/ci.yml`, push to `main`/`feature/**` + PRs to `main`): backend = install both requirements files + `pytest` on **Python 3.11**; frontend = `npm ci` + `npm run build` on **Node 20**.

## Gotchas

- Dependencies use **`httpx2`, not `httpx`** (Starlette's `TestClient` now expects httpx2; `httpx2>=0.28.0` resolves to 2.x). Don't "fix" it back to `httpx`.
- Missing `pytest-asyncio` (i.e. skipping `requirements-dev.txt`) causes `Unknown config option: asyncio_mode` warnings.
- Database is **stdlib `sqlite3`, not SQLAlchemy** — `docs/ARCHITECTURE.md` still says SQLAlchemy; trust the code.
  - File: `backend/safegrid.db` (gitignored). Tests use `Database(db_path=":memory:")` (one shared connection).
  - Repository functions (`backend/app/db/repository.py`) take a `database=` kwarg; call them, never raw SQL.
- Internal models are Pydantic `Hazard` / `RiskResult` in `backend/app/models/hazard.py`. DB rows are **flat dicts with `latitude`/`longitude`**, not the `GeoPoint` object; `save_hazard()` accepts either a dict or the model.
- `frontend/public/` does not exist. The PWA manifest is generated by `VitePWA` in `frontend/vite.config.js`; the icons it references are missing (build still passes).

## Conventions

- **Never push to `main`.** PR + one review; [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `test:`) — see `docs/CONTRIBUTING.md`.
- Ownership boundaries (`docs/ARCHITECTURE.md` §2): `backend/app/` (API/ingestion), `backend/app/risk/` + `backend/tests/test_risk/`, `frontend/`, `backend/app/db/` + `frontend/src/offline/` + `frontend/src/service-worker.js`. Stay inside your subsystem's directory; cross-subsystem changes need the owner.
- All frontend fetches go through `frontend/src/api/client.js` — never inline `fetch()` in UI. Caching belongs only in the service worker. Responses expose `is_live`, and the UI must distinguish live vs. cached data.
- Risk thresholds must be documented in `docs/RISK_MODEL.md` (value, meaning, justification, source, limitations) **before** implementing classification logic. Never invent thresholds to make demos look good — same rule in `docs/ARCHITECTURE.md` §5 and `Brain-Part-1.md` §5.
- When you change an interface, update `docs/API.md` / `RISK_MODEL.md` / `OFFLINE.md` and add a row to the change-log tables in those files and `docs/ARCHITECTURE.md`.
- Branch names in `README.md` / `docs/CONTRIBUTING.md` are stale; actual remote branches are `feature/data-ingestion`, `feature/database`, `feature/frontend-maplibre-ui`. Check `git branch -r` before creating one.
- AI-generated code must be fully understood by its owner before merge (`docs/CONTRIBUTING.md`).
- Project constraints (`README.md`): academic project, not a certified emergency system; never claim disaster prediction; offline mode serves cached data only, and "LOW" risk does not mean safe.
